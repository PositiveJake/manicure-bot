# 💅 Бот записи на маникюр

Телеграм-бот для салона/мастера маникюра: клиенты записываются через календарь,
владелец управляет записями и клиентами, напоминания приходят за день до сеанса.

## Возможности

**Для клиента:**
- 📅 Запись через месячный календарь: видны только дни со свободными слотами,
  прошедшие дни недоступны, можно листать месяцы вперёд.
- 🕒 Выбор времени из свободных слотов (занятые автоматически скрываются,
  двойная запись на одно время невозможна).
- 📋 «Мои записи» с отменой (в два нажатия, чтобы не отменить случайно).
- 📞 Указание телефона (с проверкой формата).
- Напоминание за день до сеанса.

**Для владельца (кнопка «🛠 Панель владельца»):**
- 📅 Календарь записей на месяцы вперёд и назад: на каждом дне показано количество записей,
  внутри дня — список записей с именем и телефоном клиента.
- 🗑 Отмена любой записи — клиенту придёт уведомление.
- 👥 Список клиентов (с пагинацией) и карточка клиента: имя, @username, телефон,
  будущие записи, блокировка.
- 🚫 Блокировка/разблокировка клиентов: заблокированный не может ничего нажимать в боте.
- 📨 Список записей на ближайшие 7 дней.
- Уведомления: о новых клиентах, новых и отменённых записях, дневной дайджест напоминаний.
- 📤 Резервная копия базы: команда `/backup` и автоматическая отправка файла базы в чат раз в сутки.

**Напоминания:** клиенту и владельцу за день до сеанса. Проверка выполняется каждую минуту,
поэтому напоминание не потеряется: если бот был выключен или запись сделана позже часа
напоминания накануне — оно уйдёт при первом же запуске/проверке.

## Быстрый старт

1. Нужен Python 3.10+ (проверено на 3.14).
2. Установите зависимости (один раз):

   ```
   pip install -r requirements.txt
   ```

3. Заполните файл `.env` (лежит рядом с ботом):

   ```
   BOT_TOKEN=токен_от_@BotFather
   OWNER_ID=ваш_telegram_id
   ```

   Свой Telegram ID можно узнать у бота [@userinfobot](https://t.me/userinfobot).
4. Запустите:

   ```
   python bot.py
   ```

5. В канале/группе закрепите ссылку на бота: `t.me/<имя_бота>` — клиенты пишут ему в личку.

## Настройки `.env` (необязательные)

| Переменная              | По умолчанию | Описание |
|-------------------------|--------------|----------|
| `PROXY_URL`             | —            | Прокси для Telegram API, если он заблокирован, напр. `http://127.0.0.1:1080` |
| `CHANNEL_URL`           | —            | Ссылка на канал — добавит кнопку «📣 Наш канал» в меню |
| `OWNER_IDS`             | —            | Дополнительные владельцы через запятую (напр. `123,456`) |
| `WORK_START`            | `10`         | Час начала работы |
| `WORK_END`              | `20`         | Час, к которому должен закончиться последний сеанс |
| `SLOT_MINUTES`          | `45`         | Длина сеанса в минутах |
| `BOOKING_MONTHS_AHEAD`  | `2`          | На сколько месяцев вперёд можно записываться |
| `REMINDER_HOUR`         | `12`         | Час напоминания «за день до» |
| `REMINDER_MINUTE`       | `0`          | Минута напоминания |
| `BACKUP_HOUR`           | `3`          | Час суточного авто-бэкапа базы в чат владельцу |
| `DB_PATH`               | `bookings.db`| Путь к базе (на Railway: `/data/bookings.db` + том к `/data`) |
| `TZ_NAME`               | —            | Часовой пояс салона, напр. `Europe/Moscow` (обязательно на сервере!) |
| `TZ_OFFSET_HOURS`       | —            | Или смещение от UTC в часах, если `TZ_NAME` не сработал |

## Деплой на ClawCloud Run (бесплатно, 24/7 без компьютера)

Бот живёт в контейнере на [ClawCloud Run](https://run.claw.cloud), база — на постоянном
томе, управление — с телефона через панель владельца. Платформа даёт **$5 кредитов каждый
месяц** — для бота такого размера этого хватает с запасом. Условие: вход через GitHub-аккаунт
старше 180 дней (иначе кредит только на первый месяц).

### Подготовка (уже сделана в проекте)

- `Dockerfile` — образ с ботом (Python 3.12, `DB_PATH=/data/bookings.db`, `TZ_NAME=Europe/Moscow` внутри образа);
- `.github/workflows/docker.yml` — при каждом `git push` GitHub сам собирает образ и кладёт
  его в GHCR (реестр образов GitHub);
- команда `/backup` — файл базы в чат; **пришлите этот файл боту обратно** — база
  восстановится (файл проверяется целостность, затем бот перезапускается).

### Шаги

1. **GitHub**: создайте репозиторий (проще публичный — в коде нет секретов) и загрузите
   проект из папки бота (Git для Windows уже установлен; при первом push откроется окно входа):

   ```
   git remote add origin https://github.com/<ваш-логин>/manicure-bot.git
   git push -u origin main
   ```

2. Дождитесь окончания сборки: на GitHub откройте вкладку **Actions** — должен появиться
   зелёный прогон, а в разделе **Packages** — пакет `manicure-bot`.
3. Сделайте пакет публичным: **Packages → manicure-bot → Package settings →
   Change visibility → Public** (иначе ClawCloud не сможет скачать образ без пароля).
4. **ClawCloud**: войдите на [run.claw.cloud](https://run.claw.cloud) через GitHub →
   **App Launchpad → Create App**:
   - **Image**: `ghcr.io/<ваш-логин>/manicure-bot:latest`
   - **CPU / RAM**: 0.5 vCPU / 512 MB (для бота достаточно)
   - **Network**: публичный доступ не нужен — выключите (бот работает через исходящие соединения)
   - **Environment Variables**: `BOT_TOKEN` = токен от @BotFather, `OWNER_ID` = ваш Telegram ID
     (`DB_PATH` и `TZ_NAME` уже заданы в образе; при желании переопределите)
   - **Volumes**: подключите том, mount path `/data`, объём 1 GB
   - Нажмите **Deploy**.
5. Готово: в чат придёт «🤖 Бот записи запущен». Логи — в приложении во вкладке Logs.

### Обновление бота

`git push` → GitHub Actions соберёт новый образ → в ClawCloud откройте приложение и
нажмите **Update/Restart**, чтобы подтянуть свежий образ. База на томе сохраняется.

### Если случилось худшее

Данные живут на томе `/data` и переживают перезапуски. Если том утерян — возьмите файл
из ежедневного бэкапа (он в вашем чате) и просто отправьте его боту: бот проверит,
подменит базу и перезапустится. Всё управление — из Telegram, компьютер нужен только
для `git push` при обновлениях.

### Альтернатива — Railway

В репозитории есть `railway.toml` и `nixpacks.toml`: в Railway достаточно подключить
репозиторий, задать переменные и том `/data` (подробно в истории коммитов/README Railway-версии).
Railway платный ($5/мес), зато деплой оттуда проще.

### Важно

- `.env` не попадает на GitHub (исключён через `.gitignore`) — на Railway переменные
  задаются в панели.
- Том обязателен: без него база стирается при каждом обновлении бота.
- Если что-то случится с сервером — из файла бэкапа (приходит в чат ежедневно)
  всё восстанавливается: подключите том, положите `bookings.db` на место, перезапустите.

## Проверка без Telegram

Логика (база, календари, напоминания) покрыта тестами — запуск:

```
python test_logic.py
```

## Файлы

- `bot.py` — запуск, диспетчер, обработчик ошибок
- `client_handlers.py` — запись, «Мои записи», телефон
- `admin_handlers.py` — панель владельца
- `keyboards.py` — все кнопки и календари
- `database.py` — SQLite (файл `bookings.db` создаётся сам)
- `reminders.py` — цикл напоминаний
- `config.py` — чтение настроек из `.env`

База (`bookings.db`) — обычный файл SQLite: его можно копировать как бэкап.
